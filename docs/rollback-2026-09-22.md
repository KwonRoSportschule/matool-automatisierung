## Vorgehen bei Problemen

Für den gezielten Ex-Mitglieder-Fix vom 23.09. ist die unmittelbar vorherige
Version `ab1a5b63-eb41-4c15-a375-c228f1438065` der bevorzugte Code-Rückweg.
Sie enthält bereits Leerwochenkorrektur und Strukturdiagnose. Die ältere
Version oben bleibt die dokumentierte Ausgangsbasis. Ein reiner Code-Rollback
löscht keinen inzwischen importierten Ex-Mitglieder-Bestand.

1. Bei einer reinen Code-Regression den Worker gezielt auf die oben genannte
   Version zurückrollen. Keine Datenbank zurücksetzen, wenn nur Code betroffen
   ist; so bleiben seit der Sicherung eingelesene Daten erhalten.
2. Vor einer späteren Datenbereinigung deren genaue Tabellen, Auswahl und
   Zeitpunkt dokumentieren und die betroffenen Zeilen erneut sichern.
3. Falls nötig, zuerst eine **separate** lokale oder neue Testdatenbank aus dem
   Export herstellen. Fehlende Altzeilen daraus selektiv wiederherstellen.
4. Ein vollständiges Zurücksetzen der laufenden Datenbank ist nur das letzte
   Mittel: Es würde auch erfolgreiche Synchronisationen nach dem Sicherungs-
   zeitpunkt zurücknehmen und erfordert einen koordinierten Wartungsschritt.

Bis zu diesem Stand wurden keine Tabellen oder fachlichen Daten gelöscht,
keine Migration remote ausgeführt und keine ausgehenden Aktionen aktiviert.
